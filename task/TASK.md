## 1. Ситуация

Вы работаете в команде данных площадки объявлений об аренде квартир «Квартал».
Продуктовая команда хочет, чтобы при создании нового объявления площадка
**подсказывала арендодателю рыночную цену**: человек заполняет характеристики
квартиры, а модель предлагает месячную стоимость аренды.

Для этого выгрузили опубликованные объявления за сентябрь – октябрь 2026 года.
Выгрузка сделана из рабочей системы «как есть»: её никто не проверял и не чистил.

От вас ждут:

- **модель**, которая по характеристикам квартиры предсказывает месячную
  стоимость аренды в рублях;
- **честную оценку её качества** на данных, которые модель не видела;
- **воспроизводимый код**: другой человек должен склонировать репозиторий,
  установить окружение и получить те же результаты, а модель — применить
  к новой выгрузке того же формата.

## 2. Что требуется сделать

Работа состоит из трёх этапов.

### Этап 1. Подготовка данных — один или несколько ноутбуков (как пример: `notebooks/01_preparation.ipynb`, `notebooks/02_feature_engineering.ipynb` и т.д.)

1. **Загрузить сырой файл** из `data/raw/` и убедиться, что он прочитан
   правильно: кодировка, разделитель и т.д.

2. **Сразу отделить тестовую выборку.** До разбиения допускается только то,
   что не использует статистики по данным:
   - чтение файла и приведение типов;
   - удаление точных дублей (иначе копия строки может попасть и в обучение, и в тест);
   - удаление строк с пустым значением целевой переменной.

   Всё, что «учится» на данных (медианы для заполнения, границы выбросов,
   набор категорий для кодирования, параметры масштабирования и т. п.),
   считается **только по обучающей части**.

   Тестовая часть сохраняется в `data/interim/` **в исходном виде (с такой же кодировкой, разделителями и т.д, как при чтении входного сырого файла, формат файла - .csv), до какой-либо обработки** — скрипт этапа 3 подаёт в модель именно сырые данные.

   Также нужно разбить оставшийся данные на **train / validation**.

3. **Аудит, препроцессинг, визуализация, обработка выбросов, конструирование признаков** обучающей части:
   Подготовка и визуализация данных, обосновать выбор алгоритмов. 
   Подготовка данных может быть реализована как с помощью объекта Pipeline (данный подход будет выше оцениваться), так и без него.
   Подготовка данных должна иметь фиксированный random state, чтобы другой человек, запустивший ваши ноутбуки, получил одинаковые
   артефакты (подготовленные данные, Pipeline объекты и т.д.).

4. **Сохранить результат:** подготовленную обучающую и валидационную часть 
   (данные для моделирования, Pipeline объекты и др. артефакты).
   Данные сохраняйте в `data/processed/`
   Pipeline объекты сохраняйте в `models/` в формате joblib.

5. Ноутбуки сохраняем в папку `notebooks/`

6. Повторяющийся куски кода, подходы, которые разумно вынести в функцию, класс и т.д. закидывайте в папку `modules/` в качестве модулей Python.

### Этап 2. Моделирование — `notebooks/0(n)_modeling.ipynb`

1. Обучить **baseline** (`DummyRegressor`) и модели: например, линейную или
   регуляризованную, дерево решений, kNN и т.д.
2. Посчитать метрики качества на validation и свести их в одну таблицу.
3. **Выбрать лучшую модель.** Заранее назовите метрику, по которой выбираете,
   и объясните, почему именно она.
4. **Интерпретировать** выбранную модель, если это возможно: коэффициенты,
   важности признаков, permutation importance — и что из них следует.
5. **Анализ регрессионных остатков:** распределение остатков, остатки
   против прогноза, ошибки по сегментам (например, по районам или
   ценовым диапазонам), объекты с наибольшей ошибкой и т.д.
6. **Выводы:** насколько модель пригодна для подсказки цены, где она
   ошибается сильнее всего и почему, что можно улучшить. 
   
   **Возможно после анализа необходимо сделать дополнительные ноутбуки подготовки данных, затем снова переобучая новую модель, можем получить лучше качество.**

7. **Сохранить** лучшую модель в `models/`.

Тестовая выборка на этом этапе **не используется** ни для обучения,
ни для выбора модели или гиперпараметров.

### Этап 3. Инференс на тесте — `inference.py`

Данный скрипт должен делать следующее:

1. Загрузить сохранённую модель (параметры предобработки и др. артефакты, если они
   хранятся отдельно и **нужны для предсказания**) и **сырую** тестовую выборку.
   **Данный скрипт обязательно должен иметь параметр командной строки --test_path - путь к сырой тестовой выборке**
2. Получить прогнозы через функцию `predict`.
3. Посчитать **R², MAE, RMSE на всём тесте** — это обязательно.
4. Сохранить предсказания

   в той же папке, где находилась тестовая выборка, 
   сохранить такую же тестовую выборку с дополнительной колонкой `predict`.
   Файл назвать  `{test_filename}_predicts.csv`, где `{test_filename}` - название тестового файла без расширения (.csv)
5. Сохранить значения метрик

   в той же папке, где находилась тестовая выборка, 
   сохранить текстовый файл в котором будет одна строка:

   R2={значение}|MAE={значение}|RMSE={значение}

   Файл назвать  `{test_filename}_metrics.txt`, где `{test_filename}` - название тестового файла без расширения (.csv)

### Воспроизводимость

- Используйте **фиксированный random seed**: одна константа
  (например, `RANDOM_STATE = 42`) во всех местах, где есть случайность, —
  разбиение данных, модели со случайностью, перемешивание. Повторный запуск
  ноутбуков должен давать те же числа.
- Все графики и таблицы получены исполнением кода. **Числа в тексте должны совпадать с выводом кода.** 
  Это проверяется.

## 4. Что сдавать

Репозиторий с именем `Surname_Name_Lab2`, публичный.

### Структура репозитория

```
Surname_Name_Lab2/
├── README.md                    инструкция запуска и описание файлов
├── requirements.txt             окружение с точными версиями (можно вместо requirements.txt использовать другие артефакты состояния библиотек)
├── inference.py                 скрипт для предсказания на тестовых данных
├── notebooks/                   Ноутбуки подготовки и моделирования данных
├── data/
│   ├── raw/                     выданные файлы варианта
│   ├── interim/                 сырая тестовая выборка 
│   └── processed/               подготовленные данные для моделирования
├── models/                      сохранённые модели (.joblib), артефакты Pipeline
└── modules/                     код, вынесенный из ноутбуков
    ├── __init__.py
    ├── …
    └── … 
```

Обязательные файлы:

- README.md
- requirements.txt или любые другие артефакты состояния библиотек
- inference.py
- notebooks/
- models/
- modules/

Данные (папка data/) не должны отслеживаться гитом.

Обязательно должны быть в гите все артефакты, которые нужны для файла прогноза inference.py.

### `README.md`

- как настроить окружение: версия Python, установка зависимостей
  (`pip install -r requirements.txt` или другим образом), откуда запускать Jupyter, чтобы
  работал `import modules…` и т.д.;
- в каком порядке запускать ноутбуки;
- описание каждого файла и папки репозитория;
- коротко: какая модель выбрана и какое у неё качество на тесте.

Критерий проверки: **на чистом клоне** репозитория после установки
окружения все ноутбуки исполняются в указанном порядке (01, 02, ....)
без ошибок.

### Модели в `models/`

- **Лучшая модель обязательна.** Остальные модели — по желанию.
- **Если предобработка собрана в `Pipeline` / `ColumnTransformer`** —
  сохраняйте один объект, в котором предобработка и модель идут вместе:
  он принимает признаки в исходном виде и сразу возвращает прогноз.
  Такая работа оценивается выше.
- **Если предобработка написана вручную** — кроме модели обязательно
  сохраните все параметры, выученные на train: значения для заполнения
  пропусков, границы выбросов, категории для кодирования, параметры
  масштабирования и т. п. Без них предобработку на новых данных повторить
  нельзя, а пересчитать её по тесту — значит допустить утечку. 
  Также сохраняйте другие артефакты, которые вы считаете необходимыми для инференса.
- **Если вы пишете собственные трансформеры** (реализация классов для `Pipeline`),
  они должны лежать в `modules/`, а не в ноутбуке. Иначе `joblib.load`
  в другом ноутбуке не найдёт класс и упадёт с ошибкой.

## 5. Чем можно и чем нельзя пользоваться

**Нельзя — готовые ансамбли:**
всё из `sklearn.ensemble` (`RandomForest…`, `ExtraTrees…`,
`GradientBoosting…`, `HistGradientBoosting…`, `AdaBoost…`, `Bagging…`,
`Stacking…`, `Voting…`), а также `xgboost`, `lightgbm`, `catboost`
и AutoML-библиотеки. Работа с любым из них не засчитывается.

**Про ИИ-ассистентов.** Пользоваться можно. Добавьте в README
3–5 строк: для чего использовали и что из полученного проверили сами.
На защите вы должны объяснить любую ячейку своего кода.
